Why MAID Runner

Governs the artifacts your agents produce — not just the prompts they follow.

+

Plan drift

Agents deviate from the plan and touch files you didn't ask for.

MAID's answer: An approved plan lock becomes the contract an agent can't quietly rewrite; only declared files and operations are allowed.

Test rewriting

Agents rewrite or delete tests instead of proving the fix.

MAID's answer: Tests must fail before the change (or produce equivalent red evidence), and behavioral tests prove it works. Deep verification can delete a function's body and require your tests to fail, so a gutted test can't pass. (Knockout: Python, opt-in.)

Self-reported "done"

Agents say the work is finished without proof.

MAID's answer: Structure, behavior, and scope are verified, then independently reviewed before handoff.

Rules that live in one tool

Prompt rules don't travel between agents.

MAID's answer: The manifest is the contract, so MAID runs the same under Claude Code, Codex, Cursor, Windsurf, or any harness: a deterministic, AST-level contract, not prose an agent reinterprets.

Quick start

One command installs MAID Runner on macOS, Linux, or Windows—no existing Python setup required.

See the docs for detailed guides →
terminal

macOS / Linux

curl -LsSf https://maidrunner.dev/install.sh | sh

Installs uv if it is missing, then MAID Runner as a uv tool, and adds uv's tool directory to your PATH. Read install.sh before you run it.

Pin a release: curl -LsSf https://maidrunner.dev/install.sh | sh -s -- --version <version>

Windows PowerShell

irm https://maidrunner.dev/install.ps1 | iex

Installs uv if it is missing, then MAID Runner as a uv tool, and adds uv's tool directory to your PATH. Read install.ps1 before you run it.

Pin a release: & ([scriptblock]::Create((irm https://maidrunner.dev/install.ps1))) -Version <version>

uv / pip

uv tool install maid-runner
pip install maid-runner

Already manage Python tools? Install the package from PyPI directly.

Then, in your project:

$ maid init
$ maid howto --section quickstart
✓ ready to write a verifiable change

MAID in practice

The tool is developed under the rules it enforces.

MAID Runner is not only a workflow we recommend. It is the workflow used to build and maintain the tools themselves.

Every new change can be planned, reviewed, locked, implemented, independently checked, and preserved with its validation evidence.

Private production projects

Used beyond demonstration repositories.

MAID Runner is also used across active client and internal software projects, including established brownfield systems and newly developed products.

Because those repositories contain private business and client code, their names and implementation details are not published. Their use of MAID includes:

  • scoped feature and maintenance work;
  • plan review before implementation;
  • test-driven changes with red evidence;
  • independent AI-assisted implementation review;
  • evidence-backed handoff before merge or release.
